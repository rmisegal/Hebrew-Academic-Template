Switch case prompts


=========== Common ==========================
This is a common instraction to all cases that will open the instractions
You are an expert assistant tasked with providing the highest-quality response possible. Before generating the final answer, conduct an internal reasoning process with utmost analytical rigor:

- Take a deep breath and approach the task calmly and methodically.
- Identify the core objectives, user's intent, key constraints, context, and any edge cases or potential pitfalls.
- Break the problem into clear, logical substeps. Think step by step, exploring multiple perspectives or approaches if relevant.
- Verify assumptions, evaluate logical consistency, and ensure factual accuracy throughout.
- If essential information is missing, note it internally; make reasonable assumptions only when non-essential, and state them briefly in the response if needed.
- Consider the most effective format for clarity and usability (e.g., steps, table, examples).

After thorough private reasoning and self-verification for completeness, consistency,
and precision, produce the final response: accurate, specific, actionable, 
and well-structured, directly addressing the request without fluff or unnecessary 
disclaimers.

============== Switch Case Prompt ========================

1. Case you want to learn latex book before starting update relevant chapter
Your mission is to learn the Hebrew LaTeX book project at the given path before making updates.

STEPS:
1. First, scan the project structure to identify:
   - Master/main .tex file(s)
   - Chapter files (standalone or subfiles)
   - CLS template file(s)
   - Images, bibliography, and other resources
2. Read and understand the existing structure:
   - How chapters are organized (standalone books vs subfiles)
   - Which CLS commands and functions are used
   - Formatting patterns, table styles, code blocks, etc.
3. Report back what you learned:
   - Project structure summary
   - Number of chapters found
   - Key CLS functions in use
   - Any issues or inconsistencies noticed
4. Wait for user instructions on what to update

IMPORTANT RULES:
- Do NOT compile until user explicitly asks
- Use ONLY the same CLS functions already in the project
- Match existing formatting patterns and styles
- Learn before changing anything

2. Case you want to create full markdown report on Latex Project content
Your mission is to analyze the Hebrew LaTeX book project and create a comprehensive markdown report.

STEPS:
1. Scan the entire project structure at the given path
2. For each chapter/file, extract and document:
   - Chapter title (Hebrew and English)
   - Main sections and subsections
   - Key topics covered
   - Tables (count and descriptions)
   - Figures/images (count and descriptions)
   - Code blocks (count and languages)
   - Mathematical formulas (key equations)
   - Bibliography/citations used
3. Create a structured markdown report containing:
   - Project overview (structure, CLS version, total pages estimate)
   - Chapter-by-chapter summary
   - Content inventory (tables, figures, code, formulas)
   - Cross-references map
   - Identified gaps or areas needing attention

OUTPUT FORMAT:
Create a markdown file with clear sections, tables for inventories,
and actionable insights about the project content.

4. Case you want to rerun the qa-table
Your mission is to run qa-table QA on the Hebrew LaTeX book project.

STEPS:
1. First, scan the project to identify all chapter files (.tex files)
2. Count the number of chapters found (N chapters)
3. Create a todo list with tasks for each qa-table-* skill per chapter:
   - Skills: qa-table-detect, qa-table-fancy-detect, qa-table-fancy-fix,
     qa-table-fix-align-to-right, qa-table-fix-alignment, qa-table-fix-captions,
     qa-table-fix-columns, qa-table-overflow-detect, qa-table-overflow-fix (9 skills)
   - Total tasks = 9 skills × N chapters
4. Run each skill on each chapter one by one
5. Mark each task as done when complete
6. Report summary of issues found and fixed

DYNAMIC CALCULATION:
- If book has 5 chapters → 45 tasks (9 × 5)
- If book has 10 chapters → 90 tasks (9 × 10)
- Adjust task count based on actual chapters found
